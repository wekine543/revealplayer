# RevealPlayer — 媒体叠加遮罩播放器

## 这是什么

RevealPlayer 是一个基于 WebGL 的媒体叠加播放器。你选择两个媒体源（A 和 B），A 作为默认显示层，B 作为隐藏层。播放时画面正常显示 A 的内容；当鼠标在画面上移动时，以鼠标为中心的圆形区域内显示 B 的内容，形成"探照灯"或"局部揭示"效果。

## 核心功能

| 功能 | 说明 |
|------|------|
| **媒体加载** | 支持视频（mp4/webm）和图片（jpg/png/webp/gif），可从本地文件或在线 URL 加载，支持拖拽上传 |
| **探照灯遮罩** | 鼠标移动时，圆形遮罩内显示 B 的内容，区域外显示 A，边缘带羽化过渡 |
| **比例保持** | 播放区自动跟随媒体 A 的比例（竖屏素材即竖屏画面）；媒体本身按原始比例显示，不会被拉伸，多余区域自动留黑边 |
| **视频同步** | A/B 两段视频帧级对齐（偏差 < 50ms），肉眼不可感知 |
| **A/B 时间差** | 素材本身有固定时间差时可手动补偿：-3s ~ +3s、步进 0.01s，B 快为正。调节值自动写进当前播放组合的收藏记录，旧记录默认为 0 |
| **跳过开头等待** | 从头播放时不必有人干等：默认为弹出等待，差值 > 0.1s 时默认「跳过」——靠前的一路直接从前移 N 秒处开始，另一路从 0 开始，代价是被跳过的开头不再显示。可随时手动开关 |
| **遮罩调节** | 遮罩大小（20~500px）、羽化宽度（0~100px）、边框开关/粗细/颜色/透明度，均实时预览 |
| **播放控制** | 播放/暂停、进度条拖动跳转、音量控制、倍速播放（0.5x~2x）、循环播放、全屏、截图 |
| **收藏组合** | 一键保存 A/B 搭配及所有遮罩参数，刷新页面后仍然保留，支持搜索/加载/删除/重命名；可存入配置文件夹实现跨设备迁移（见下） |
| **组合预览图** | 每个收藏在列表里显示 A 媒体的一帧预览（图片直接解码，视频取开头附近一帧），结果按会话缓存 |
| **可折叠界面** | 整个侧边栏可隐藏，遮罩设置、时间差与收藏夹也可各自折叠，让画面占据更大空间 |
| **设置记忆** | 遮罩参数、循环、音量、倍速、面板折叠状态自动保存，下次打开沿用上次设定 |
| **移动端适配** | 手机上自动切换布局，支持手指拖动揭示；自动限制渲染分辨率以缓解卡顿。竖屏窗口（高>宽）同样使用该布局 |

## 技术栈

- **React 19 + TypeScript** — 前端框架
- **Three.js + WebGL** — GPU 渲染，自定义 GLSL 着色器实现遮罩混合
- **Zustand** — 状态管理
- **Tailwind CSS** — 界面样式
- **IndexedDB** — 本地文件和收藏组合的持久化存储

## 如何使用

### 方式一：双击打开（推荐，零门槛）

桌面上的 `RevealPlayer.html` 文件，**双击即可用浏览器打开**，无需安装任何环境、无需终端命令。所有功能（媒体加载、遮罩、收藏等）均可正常使用。

> 如需重新生成此文件，在项目目录执行 `npm run build`，产物在 `dist/index.html`。

### 方式二：一键启动脚本（开发模式）

双击项目目录下的 `RevealPlayer.bat`，会先启动本地服务器、等它就绪后再打开浏览器（不会出现「localhost 拒绝了连接请求」）。用完后关闭弹出的终端窗口即可。

想让**手机/平板**也能访问，改用 `RevealPlayer-LAN.bat`（会监听局域网并打印 IP，详见「服务端存储」一节）。

npm run dev
```

浏览器打开 `http://localhost:5174` 即可使用。关闭时在终端按 `Ctrl + C`。

```

## 配置文件夹：让收藏可以随身带走

收藏组合默认存在浏览器的 IndexedDB 里，清理浏览器数据就会丢失，也没法带到另一台机器。配置文件夹解决这个问题：把组合信息和媒体文件一起放到你自己指定的磁盘目录里。

### 目录结构

```
<你选择的文件夹>/
├── revealplayer.config.json    # 组合信息 + 遮罩设定
└── media/
    ├── clip-a.mp4              # A 槽的媒体文件
    └── clip-b.mp4              # B 槽的媒体文件
```

JSON 里用**相对路径**引用媒体（例如 `media/clip-a.mp4`），所以整个文件夹拷到 U 盘或另一台电脑上照样能打开。

### 使用流程

1. 首次启动会弹窗让你选一个文件夹（也可以选「暂时跳过」，之后在右侧「Saved Combos」里再选）
2. 选好后，每次保存组合时会把两个媒体文件复制进 `media/`，并把组合写入 JSON
3. 下次启动自动读取该文件夹的 JSON，恢复组合列表和遮罩设定
4. 换设备时：拷走整个文件夹 → 在新设备上打开应用 → 选择这个文件夹

侧边栏「Saved Combos」顶部会显示当前存储位置，可随时「更改」或「断开」。

### 点击文件夹名直接打开本地文件夹

点击状态条里的文件夹名，会在资源管理器 / Finder 中打开该文件夹。

浏览器只肯告诉应用文件夹的**名字**，不告诉**路径**（File System Access API 故意不暴露），所以第一次点击时会做一次定位：开发服务器在常见位置（桌面、文档、下载、各盘根目录，深度 3 层以内，4 秒上限）搜索同名文件夹；找不到就弹出窗口让你浏览或手动粘贴路径。定位结果会记住，之后点击就是直接打开。

这个功能依赖 `RevealPlayer.bat` 启动的本地服务（`/__rp/fs`）。用 `dist/index.html` 双击打开时没有服务端，点击会提示需要用 .bat 启动。

### 环境要求

| 项目 | 说明 |
|------|------|
| 浏览器 | Chrome / Edge（依赖 File System Access API），Firefox、Safari 不支持 |
| 打开方式 | 必须 `http://localhost` 或 https —— **双击 HTML 的 `file://` 模式不支持读写本地文件夹** |

`file://` 下不会再弹提示条：功能不受影响，只是收藏回落到浏览器本地存储，侧边栏「Saved Combos」顶部会显示当前实际使用的存储位置。

### 几点说明

- **是复制，不是移动**：浏览器没有权限删除原位置的文件，所以保存时是把文件**复制**进配置文件夹，原文件保留。已经在配置文件夹里的文件不会重复复制（按文件名去重）。
- **在线 URL 媒体保持原样**：URL 本身在任何设备上都能访问，不会再下载一份。
- **授权的持久化**：目录句柄存在 IndexedDB 里，浏览器通常每次会话需要确认一次权限；启动时会显示「重新授权」按钮，点一下即可。

## 服务端存储：让手机也能用上收藏

配置文件夹依赖 File System Access API，而**手机浏览器拿不到它**（iOS Safari 完全不支持；Android Chrome 132+ 虽然有，但手机通过 `http://192.168.x.x` 访问时不是安全上下文，API 同样不可用）。所以又加了第三种存储后端：**把组合和媒体文件放在运行服务的那台电脑上**。

手机不需要任何浏览器 API，只要能访问到 PC 就能完整使用：保存、加载、预览图、改名、删除、遮罩同步全部可用。

### 怎么用

1. 在 PC 上双击 **`RevealPlayer-LAN.bat`**（不是 `RevealPlayer.bat`）—— 它会监听 `0.0.0.0` 并打印本机局域网 IP
2. 手机连同一个 Wi-Fi，浏览器打开 `http://<PC 的 IP>:5174`
3. 侧边栏「Saved Combos」顶部点 **服务端存储** → 选一个目录（可以直接填还不存在的路径，会自动创建）
4. 之后手机和 PC 看到的就是同一份收藏

目录结构和配置文件夹完全一致，两边可以互相拷贝复用：

```
<服务端存储目录>/
├── revealplayer.config.json
└── media/
    └── clip-a.mp4
```

存储目录的位置记在项目根目录的 `.revealplayer-store.json` 里；「更改」可以随时换，「切换」在三种后端之间轮换（服务端存储 / 配置文件夹 / 浏览器本地）。

### 注意

| 项目 | 说明 |
|------|------|
| 需要 PC 开机并跑着服务 | 手机离开局域网、或者 PC 关掉服务后，服务端存储的组合就读不到了（浏览器本地的不受影响） |
| 单文件模式无服务端 | 双击 `dist/index.html` 没有服务，会自动回落到浏览器本地存储 |
| 局域网暴露 | `--host` 会让同一网络里的其他设备访问到应用和本地辅助服务（列目录、打开资源管理器）。**不要在不信任的网络里用**；日常只给电脑自己用就继续用 `RevealPlayer.bat` |

## 移动端使用

在手机上打开时，界面会**自动切换为适应手机的布局**，无需任何设置：

- **播放区跟随内容比例**：导入的 A 是竖屏，播放区就自动变成竖屏比例，不会出现大片黑边；导入横屏内容则自动变回横屏
- **A/B 选择区始终同排**：两个选择区并排显示并整体缩小，把竖直空间让给播放区
- **上下堆叠排列**：画面、播放栏、媒体加载区依次向下排列，侧边栏（遮罩设置、收藏夹）变成全宽并移到最下方
- **手指拖动揭示**：在画面上按住并滑动手指，遮罩会跟随手指移动显示 B 的内容，松手后恢复显示 A
- **调节遮罩大小**：手机上没有滚轮，展开「Mask Settings」用 Radius 滑块调节
- **顶部按钮只显示图标**：点击右上角按钮可展开/收起整个侧边栏
- **首次打开**默认折叠侧边栏，让画面占据最大空间
- **横屏时**播放区高度会自动限制，避免超出屏幕

### 移动端性能优化

手机端会自动启用省电模式（页脚会显示提示），以缓解大分辨率视频的卡顿：

| 措施 | 说明 |
|------|------|
| **压缩视频纹理** | 这是**唯一随源分辨率增长**的开销。视频帧作为纹理上传时，4K 单帧约 33MB，30fps 就是约 1GB/s 的带宽。超过 1280px 的素材会先缩放再上传，4K 可减少约 90% 的每帧数据量 |
| **遮罩未打开时跳过 B 的上传** | B 只在遮罩圆圈内可见。遮罩关闭时完全不向 GPU 上传 B 的纹理（实测 120 帧渲染中 B 上传 0 次），B 仍在正常解码播放，因此遮罩一打开就是同步帧，不会跳帧 |
| 按解码帧渲染 | 视频按源帧率（常为 24/25/30fps）出帧，屏幕却是 60Hz+。同一帧不再重复上传和重复绘制 |
| 限制像素比 | 渲染像素比上限 1.5（桌面为 2） |
| 限制渲染分辨率 | 绘制缓冲最大 1280×720（720P），超出则自动降低像素比 |
| 关闭多重采样抗锯齿 | 遮罩边缘、羽化、边框由着色器渐变生成，本就平滑，无需 MSAA |
| 关闭绘制缓冲保留 | 移动端不再每帧复制缓冲；截图改为渲染后同步读取 |
| 空闲时跳过绘制 | 暂停且手指静止时不再重复渲染，降低耗电与发热 |

> **注意**：以上措施降低的是**渲染与纹理上传**开销。视频**解码**由浏览器负责，不受此影响 —— 4K 源视频在手机上仍会吃力，建议手机端使用 1080p 及以下的素材。

### 如果仍然卡顿

按影响从大到小依次尝试：

1. **换素材**（最有效）。解码开销由浏览器负责，我们无法干预。除了降分辨率，**降低码率同样重要** —— 20Mbps 的 1080p 比 5Mbps 的同分辨率视频吃力得多。另外注意编码格式：H.264 在手机上普遍有硬件解码，H.265/AV1 较老机型可能回退到软件解码，性能差距极大。
2. **改小纹理上限**：`src/lib/engine.ts` 的 `TEXTURE_MAX_LONG_EDGE`（默认 1280）。
3. **继续降渲染分辨率**：`MOBILE_MAX_BUFFER_W` / `MOBILE_MAX_BUFFER_H`（默认 1280/720）或 `MOBILE_MAX_DPR`（默认 1.5）。

打开浏览器控制台可以看到当前生效的参数，以及每个素材的实际缩放情况，例如：

```
[RevealPlayer] quality tier: mobile · max DPR 1.5 · buffer cap 1280x720 · texture cap 1280px
[RevealPlayer] media A: 3840x2160 source — scaled to 1280x720 before texture upload (89% less per frame)
```

> **提示**：手机上直接打开 `RevealPlayer.html` 通常无法加载本地文件（浏览器限制）。建议把该文件放到手机可访问的服务器上，或使用 URL 方式加载媒体。

## 响应式断点

| 断点 | 宽度 | 布局 |
|------|------|------|
| 手机 | < 640px | 上下堆叠；A/B 选择区同排并缩小；播放区高度上限 56dvh；按钮只显示图标 |
| 平板 | 640px ~ 1023px | 播放区高度上限 64dvh；侧边栏仍在下方全宽 |
| 桌面 | ≥ 1024px 且**横屏** | 三列布局：左侧贴边为 Mask Settings + Sync Offset + A/B 选择区，中间为播放区（占满剩余高度，与页面底部对齐），右侧为 Saved Combos（宽度可拖拽，220~720px，记忆保存） |
| 竖屏窗口 | 高度 > 宽度 | 无论多宽都使用堆叠布局（例如竖放的分屏窗口、竖屏显示器），与手机布局一致 |

播放区比例不由断点决定，而是**始终跟随媒体 A 的实际比例**（竖屏素材即竖屏画面）。未加载媒体时默认 16:9。

### 桌面三列布局

- **左列**（贴浏览器左边缘）：Mask Settings、Sync Offset、A/B 媒体选择区 + Swap 按钮；列内容超高时整列滚动
- **中列**：播放区 + 播放栏。页面锁定为一屏高，播放区自动吃掉左右两列剩下的全部空间，控制区贴着页面底部
